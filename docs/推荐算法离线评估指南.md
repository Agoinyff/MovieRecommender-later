# 推荐算法离线评估指南（Recall / F1 / Coverage）

本文档配套脚本：`scripts/evaluate_recommenders.py`。

目标：比较 `USER_BASED`、`ITEM_BASED`、`SLOPE_ONE` 三种策略在**同一数据切分**上的 Recall@K、F1@K、Coverage@K。

---

## 1. 能力说明

脚本支持以下完整流程：

1. 自动备份 `movie_preferences`
2. 自动按时间切分 train/test（每用户留最后 N 条作测试）
3. 用 train 覆盖 `movie_preferences`，触发模型重建
4. 调用 `/api/recommendations` 对三种策略评估
5. 导出两份 CSV：
   - `eval_summary_*.csv`（策略汇总指标）
   - `eval_per_user_*.csv`（用户级明细）
6. 评估完成后自动恢复 `movie_preferences` 并重建模型

---

## 2. 前置条件

- 后端服务已启动，默认：`http://127.0.0.1:8080/api`
- MySQL 可连接，且目标库包含：
  - `movie_preferences`
  - `movies`
- Python 3.8+
- 安装依赖：

```bash
pip install pymysql requests
```

---

## 3. 一键运行示例

```bash
python3 scripts/evaluate_recommenders.py \
  --db-host 127.0.0.1 \
  --db-port 3306 \
  --db-user root \
  --db-password '你的密码' \
  --db-name movie \
  --api-base http://127.0.0.1:8080/api \
  -k 10 \
  --min-ratings 5 \
  --holdout-per-user 1 \
  --output-dir ./reports
```

---

## 4. 参数说明

- `-k`：Top-K，必须 `<=50`（接口限制）
- `--min-ratings`：每个用户最少评分数，低于该值不纳入评估
- `--holdout-per-user`：每用户留作测试的最后 N 条
- `--model-timeout-s`：等待 `/model/status` 变为 SUCCESS 的超时时间
- `--request-timeout-s`：推荐接口请求超时
- `--output-dir`：CSV 输出目录

---

## 5. 输出数据说明

## 5.1 汇总报告 `eval_summary_*.csv`

字段：

- `strategy`：策略名
- `users`：参与评估的用户数
- `k`：Top-K
- `precision_at_k`
- `recall_at_k`
- `f1_at_k`
- `coverage_at_k`
- `distinct_recommended_items`
- `catalog_size`

## 5.2 用户明细 `eval_per_user_*.csv`

字段：

- `strategy`, `user_id`
- `truth_count`, `pred_count`, `hit_count`
- `precision_at_k`, `recall_at_k`, `f1_at_k`
- `truth_movie_ids`, `pred_movie_ids`

---

## 6. 指标定义

- Recall@K = `|R∩T| / |T|`
- Precision@K = `|R∩T| / K`
- F1@K = `2PR / (P+R)`
- Coverage@K = `去重推荐电影数 / 全部电影数`

其中：
- `R` 为 Top-K 推荐集合
- `T` 为测试集中用户真实交互电影集合

---

## 7. 常见问题

1. **报错“评估用户数为 0”**
   - 降低 `--min-ratings`
   - 检查 `movie_preferences` 数据量

2. **报错“模型重建超时”**
   - 增大 `--model-timeout-s`
   - 检查后端日志与 `/api/model/status`

3. **担心污染线上数据**
   - 脚本会自动备份与恢复 `movie_preferences`
   - 建议仍在测试环境执行
