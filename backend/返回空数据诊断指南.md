# 返回空数据诊断指南

## 🔍 问题现象

- 推荐接口返回 `200` 状态码
- 响应体是空数组 `[]`
- 每次请求都显示"缓存未命中"

## 📋 诊断步骤

### 步骤 1: 检查预热状态

**访问健康检查接口**：
```bash
curl http://localhost:8080/api/health/warmup-status
```

**预期结果**：
```json
{
  "warmedUp": true,
  "status": "已预热完成",
  "numUsers": 162542,
  "numItems": 15234,
  "cacheStatus": "缓存命中"
}
```

**可能的问题**：

#### 问题 A: `warmedUp: false`
**原因**：预热失败或未完成

**解决方案**：
1. 查看应用启动日志，搜索 "预热"
2. 检查是否有异常堆栈
3. 确认数据库连接正常

#### 问题 B: `cacheStatus: "缓存为空"`
**原因**：缓存配置问题或预热未成功写入缓存

**解决方案**：
```bash
# 检查缓存配置
curl http://localhost:8080/api/health/cache-stats

# 重启应用，观察启动日志
```

### 步骤 2: 检查用户是否存在

**检查用户1是否在数据模型中**：
```bash
curl "http://localhost:8080/api/health/check-user?userId=1"
```

**预期结果**：
```json
{
  "userId": 1,
  "exists": true,
  "status": "用户存在于数据模型中",
  "ratingsCount": 45
}
```

**可能的问题**：

#### 问题 C: `exists: false`
**原因**：用户1不在采样的数据范围内

**这是最可能的原因！**

**解释**：
- 当前配置：采样率 50%，加载最近的 1600万条评分
- 如果用户1的评分都比较旧（不在最近的1600万条中），就不会被加载
- 数据模型中没有用户1，所以返回空推荐

**解决方案**：

##### 方案 1: 使用全部数据（推荐）
编辑两个文件的 `SAMPLE_RATE`：
- `RecommendationService.java`
- `DataModelWarmer.java`

```java
// 改为 1.0（加载全部数据）
private static final double SAMPLE_RATE = 1.0;
```

然后重新编译启动：
```bash
mvn clean package -DskipTests
start.bat
```

##### 方案 2: 检查用户1是否有评分记录

**连接数据库执行SQL**：
```sql
-- 检查用户1是否有评分
SELECT COUNT(*) FROM movie_preferences WHERE userID = 1;

-- 查看用户1的评分时间戳
SELECT * FROM movie_preferences 
WHERE userID = 1 
ORDER BY timestamp DESC 
LIMIT 5;

-- 查看最新的评分时间戳
SELECT MAX(timestamp) as latest_timestamp 
FROM movie_preferences;

-- 查看用户1的评分是否在最近50%的数据中
SELECT 
    (SELECT COUNT(*) FROM movie_preferences WHERE userID = 1) as user1_ratings,
    (SELECT COUNT(*) FROM movie_preferences 
     WHERE timestamp >= (
         SELECT timestamp FROM movie_preferences 
         ORDER BY timestamp DESC 
         LIMIT 1 OFFSET 16000000
     )) as recent_half_ratings;
```

##### 方案 3: 测试其他用户

尝试请求其他用户ID，看是否能返回推荐：
```bash
# 尝试用户 ID 2-100
curl "http://localhost:8080/api/recommendations?userId=2&size=10&strategy=USER_BASED"
```

如果某些用户能返回推荐，说明问题确实是**用户1不在采样范围内**。

## 🎯 最可能的根本原因

根据你的描述（每次请求都缓存未命中），有两个问题：

### 问题 1: 缓存未生效 ⚠️

**原因可能是**：
1. `@EnableCaching` 注解没有生效
2. 缓存配置有问题
3. 方法调用方式不对（内部调用不走代理）

**检查**：
```bash
# 1. 确认 MovieRecommenderApplication 有 @EnableCaching
grep -n "EnableCaching" src/main/java/com/rcd/movierecommender/backend/MovieRecommenderApplication.java

# 2. 检查缓存配置
curl http://localhost:8080/api/health/cache-stats
```

**解决**：
如果 `@EnableCaching` 缺失，添加它：
```java
@SpringBootApplication
@EnableCaching  // 这个必须有
@EnableAsync
public class MovieRecommenderApplication {
    // ...
}
```

### 问题 2: 用户不在数据模型中 ⚠️

**原因**：
- 采样率 50%，只加载最近的 1600万条评分
- 用户1的评分可能都比较旧，不在最近的数据中
- 所以用户1不在数据模型中

**解决**：
使用全部数据（SAMPLE_RATE = 1.0）
