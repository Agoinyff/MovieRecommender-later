# 简化实现说明（面向本科论文）

本说明文档对应后端“最小但完整”的实现路径，强调流程清晰、易于讲解与验收。

## 目标

- 保留三种协同过滤算法（User-based / Item-based / Slope One）。
- 保留基本推荐接口与电影检索接口。
- 去掉采样、缓存、预热等工程化优化，避免实现过于复杂。
- 使用 MyBatis 直接写 SQL，流程更直观。

## 已完成的简化点

1. **数据访问层**
   - 删除 JPA Repository 与实体注解，改用 MyBatis Mapper。
   - 新增 `MovieMapper`、`RatingMapper`，直接编写 SQL 读取数据。

2. **数据模型构建**
   - `RecommendationService.buildDataModel()` 直接从 `RatingMapper` 读取评分，构建 Mahout `DataModel`。
   - 移除采样逻辑、缓存与预热，减少分支与异步复杂度。

3. **健康检查接口**
   - 仅保留 `/api/health/status` 与 `/api/health/rating-count`，便于快速确认服务可用性与数据规模。

4. **配置与依赖**
   - 移除 JPA/Hibernate 和缓存依赖与配置。
   - 新增 MyBatis 依赖与下划线映射配置。

## 运行流程（简述）

1. **客户端调用推荐接口** `/api/recommendations`
2. **服务层构建 DataModel**
   - 从 `movie_preferences` 表读取所有评分
   - 转换为 Mahout `GenericDataModel`
3. **根据策略生成推荐**
   - User-based / Item-based / Slope One
4. **批量查询电影详情并返回结果**
